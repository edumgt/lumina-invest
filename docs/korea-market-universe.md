# 코스피·코스닥 전종목 분석

2026-10-14 공식 KIS 마스터에서 확인한 범위는 2,763개 주식(코스피 939 / 코스닥 1,824), 공식 업종 28개다. 일별 마스터 갱신에 따라 숫자는 달라진다.

## 범위와 호환성

- 포함: 보통주·우선주·SPAC·상장 리츠 주식, 코스피·코스닥에 상장한 외국주·주식예탁증서.
- 제외: 코넥스, ETF·ETN, 채권·펀드·신주인수권 등 주식 외 상품.
- 거래정지·관리·정리매매 종목은 검색·분석에는 남기고 신규 매수 후보에서 제외한다.
- 기존 반도체·IT·K뷰티 리밸런싱 플랜은 별도의 기존 테마 정의로 보존한다. 기존 비중을 공식 업종 비중으로 임의 변환하지 않는다.
- 영숫자 6자리 상장코드도 목록·분석에 포함한다. 현재 ST 주문 게이트웨이는 숫자 코드만 지원하므로 영숫자 코드는 자동 매수 후보에서 제외한다.

## 데이터와 실행

`korea_universe`는 KIS의 `kospi_code.mst.zip`, `kosdaq_code.mst.zip`, `idxcode.mst.zip`을 TLS 검증을 유지해 읽는다. 고정폭 필드 형식은 KIS 공식 `stocks_info/kis_kospi_code_mst.py`, `kis_kosdaq_code_mst.py` 기준이다. ZIP을 파일시스템에 풀지 않고 필요한 파일만 메모리에서 읽는다. 제공 형식이 바뀌거나 한 시장이 누락되면 기존 정상 마스터를 유지한다.

종목 마스터의 초기 스냅샷은 `app/data/korea-universe.json`에 있고, 갱신본은 기존 PostgreSQL `DataCache`에 저장한다. 종목 목록 객체를 그대로 갱신하므로 기존 import도 새 목록을 참조한다. 기동·주기 작업에서 마스터를 갱신하고, API 프로세스는 최대 15분 간격으로 공유 DB의 목록을 확인한다.

`sync.korea_market`은 1분마다 최대 40개를 처리한다. Redis의 서비스 전용 임대 잠금으로 중복 작업을 막고, 청크마다 PostgreSQL에 진행 위치와 결과를 기록한다. 워커가 중단돼도 마지막 저장 위치부터 이어서 진행한다. 기존 DB 일봉을 먼저 읽으며, 없거나 오래되면 필요한 기간만 ST 적재 API에 요청하고, 필요하면 Yahoo 자료로 보완한다. 이 작업은 주문 API를 호출하지 않는다.

계산은 완료된 일봉 기준이다. 장중에는 당일 봉을 제외한다. 17시 이후에는 종가 자료를 위한 새 스캔 구간을 시작한다. 일봉 부족·오래됨·조회 실패·미처리는 정상 분석과 구분해서 집계한다. 수집 종료는 모든 종목의 최신 데이터 확보를 뜻하지 않는다. 제공자 오류 또는 미상장 기간 때문에 부족한 종목은 별도로 남으며, 실패·오래된 종목은 전체 스캔 이후 1시간 간격으로 최대 3회 추가 재시도한다. 화면의 다시 수집 버튼으로도 재시도할 수 있다.

## 후보와 위험관리

후보는 신선한 일봉 60개 이상, 거래 가능 마스터 상태, 최근 20일 평균 거래대금 기준을 충족한 종목에서 기존 기술지표 점수와 거래대금으로 정렬한다. 자동매매 사이클은 그 후보와 보유종목만 다시 조회한다. 배치에 실패했을 때 목록 앞 종목을 임의로 매수하는 대체 동작은 없다. 보유종목은 현재 마스터에서 사라져도 관리 대상으로 남긴다.

- `QUANT_KOREA_BATCH_SIZE=40`
- `QUANT_KOREA_CONCURRENCY=4` (최대 8)
- `QUANT_KOREA_CANDIDATE_POOL=40`
- `QUANT_KOREA_MAX_DATA_AGE_DAYS=4` (달력일; 긴 연휴에는 보수적으로 후보가 줄 수 있음)
- `QUANT_KOREA_MIN_TURNOVER_KRW=100000000` (20일 평균 1억 원)
- `QUANT_KOREA_INGEST_MISSING=true`
- `QUANT_KOREA_ALLOW_LIVE_EXPANSION=false`

실전 신규 매수 범위는 마지막 기존 31종목으로 제한하며, 전체 시장의 실전 주문 확대는 별도 승인·설정 변경 대상이다. 주문 승인·비상 정지·일손실·주문 횟수·주기·금액 등 기존 위험관리 기준은 유지한다. 직접 선택 최대 10개는 동시 거래 대상 수 제한이며, 선택 가능한 주식 목록 제한이 아니다.

## 화면과 API

- `/api/stocks/quant/list`: 전체 목록 또는 `q`, `market`, `sector`, `offset`, `limit` 조회.
- `/api/stocks/universe/status`: 마스터·처리 진행·자료 상태. 주문 또는 계좌 비밀을 포함하지 않는다.
- `/api/stocks/universe/candidates`: 신선한 배치 결과의 매수 후보.
- `POST /api/stocks/universe/scan?force=true`: 로그인한 사용자가 데이터 수집 재시작을 요청한다. 주문을 전송하지 않는다.
- `/api/stocks/signals`: 전체 시장 배치 스크리닝. 명시적으로 종목을 지정한 분석은 기존 경로로 지원한다.

기업 비교는 전체 종목에서 검색·시장·업종으로 필터하고 30종목씩 조회한다. 30은 한 페이지의 크기이며 대상 종목 제한이 아니다. 인디케이터와 직접 선택 설정도 전체 주식에서 검색한다.

섹터 화면은 저장된 배치 자료를 한 번에 읽어 집계하며, 수천 개의 외부 재무 요청을 한 HTTP 요청에서 보내지 않는다. 재무자료는 기존 캐시와 개별 기업 조회를 재사용한다. 미수집 재무지표는 N/A로 표시하고 일봉 범위·계산 가능한 점수 가중치가 부족하면 비중 판정을 ‘판단 불가’로 표시한다. 시가총액은 KIS 마스터의 현재 값(억 원)으로, 업종 지수는 현재 시총 가중 근사이지 공식 지수가 아니다.

## 운영 검증

배포에는 API·Celery worker·beat의 같은 소스 및 `app/data` 파일 반영이 필요하다. 새 DB 마이그레이션은 필요하지 않는다. 서비스 재시작과 운영 데이터 수집은 배포 승인 흐름을 따른다.

검증 시 종목 목록의 시장별 수·ETF 제외·기존 목록 밖 종목 검색, 배치 상태의 실제 처리 수·자료 기준일, 섹터 자료 범위와 신규 후보를 확인한다. 스케줄 등록 또는 카탈로그 수만으로 전종목의 최신 일봉 수집 완료를 판단하지 않는다.
